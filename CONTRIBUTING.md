# Contributing to SENTINAL

Thank you for helping build a defensive, understandable monitoring platform.

## Workflow

Issue → Specification → Implementation → Tests → Security Review → Documentation → Pull Request

Create a focused issue first. Use descriptive branches such as `feat/event-normalization` or `fix/process-parser`. Keep changes scoped, formatted, tested, and documented. Run `pytest` and `ruff check .` before opening a pull request.

Pull requests should explain the problem, approach, tests, security/privacy implications, configuration changes, and documentation updates. Do not commit secrets, private telemetry, unlicensed assets, copied code without attribution, or offensive functionality. Changes affecting collection, privilege, storage, external transmission, or action require an architecture and security review.
